# 仓位层策略优化方案（§55）

## 目标

§51 已证 G7/CS/dynamic-topk/rank-weight 在 HFLGBModel pred 上全部不如 baseline（Calmar 4.88）。本节用**新思路**改进仓位层，目标是找到能提升 Calmar（降低回撤而不大幅牺牲超额）的方案，并落地实现。

## Worktree

```
git worktree add ../5.qlib_ifind_position feat/position-sizing
```

## 框架

复用 `data/rolling_90d_result.pkl`（HFLGBModel 361 天 OOS pred/label），新建 `scripts/compare_position_sizing.py`（基于 compare_anticrowd.py 框架），一次运行输出 baseline + 全部方案的 Calmar 对比表。

## 方案清单（3 大方向，共 10 个变体）

### 方向 A：改进 G7 波动率仓位（修复 HFLGBModel 适配问题）

§51 的 G7 失败原因：full-sample median 有 mild look-ahead + vol_window=10 可能不适配 HFLGBModel 的平滑 alpha 曲线。

| 变体 | 改动 | 假设 |
|---|---|---|
| **A1** | vol_window sweep: 5/10/15/20/30 | 不同窗口适配不同 regime 周期 |
| **A2** | expanding median（仅用过去 N 天的 vol 中位数，无 look-ahead） | 消除 full-sample median 的 look-ahead |
| **A3** | 超额收益 vol（excess = portfolio - benchmark，用 excess vol 做 target） | 策略 alpha 波动 ≠ 绝对收益波动 |
| **A4** | 非对称仓位（高 vol 减仓幅度 > 低 vol 加仓幅度） | 避免对称 vol-target 在牛市过度减仓 |

### 方向 B：滚动 IC regime 择时（§54 新发现驱动）

§54 核心发现：回撤期策略 alpha 消失（top10 - pool = -0.02% vs 正常期 +1.04%）。如果能检测到"alpha 消失" regime → 减仓。

| 变体 | 实现 | 信号源 |
|---|---|---|
| **B1** | 滚动 10 日 pred IC < 阈值 → 按比例减仓 | pred 自身历史 IC |
| **B2** | 滚动 10 日 top10-pool alpha < 0 → 减仓 | top10 实际超额 vs 池均值 |
| **B3** | 滚动 IC 的 z-score：IC 低于 1σ → 半仓，低于 2σ → 1/4 仓 | IC 的统计偏离 |

### 方向 C：基准趋势连续仓位

§48 的 G1/G2 用的是 binary on/off（基准跌破均线 → 空仓），毁收益。改用连续仓位：

| 变体 | 实现 | 与 G1/G2 的区别 |
|---|---|---|
| **C1** | position = clip(基准 20 日动量 / 阈值, 0.3, 1.0) | 连续而非 binary，保底 30% 仓位 |
| **C2** | position = 1 - max(0, 基准 5 日回撤 / 10%) | 基准回撤越大仓位越低，上限 10% 回撤 → 0 仓 |
| **C3** | A + C 组合：vol-target 与基准趋势取 min | 双信号叠加 |

## 实现步骤

### Step 1：worktree + 框架搭建
- `git worktree add ../5.qlib_ifind_position feat/position-sizing`
- 创建 `scripts/compare_position_sizing.py`：load pkl → baseline + 10 个变体 → 对比表

### Step 2：运行回测 + 分析
- 运行 `compare_position_sizing.py`
- 输出对比表（excess/IR/DD/Calmar），找 Calmar > 4.88 的方案
- 对每个优于 baseline 的方案，检查是否在不同子时段稳定（非过拟合）

### Step 3：落地最优方案
- 如果找到 Calmar > 4.88 的方案：
  - 修改 `qlib_ifind_beta/td0_strategy.py`：在 `generate_trade_decision` 中加 `position_scale` 参数（默认 1.0 = 不变），通过 `risk_degree * position_scale` 实现动态仓位
  - 修改 `qlib_ifind_beta/live/inference.py` 或 `live_forward.py`：加入仓位计算逻辑
  - 新增 `qlib_ifind_beta/position_sizing.py`：仓位计算模块（纯函数，输入 = 历史收益/benchmark/IC，输出 = position float）
- 如果全部不如 baseline：落档为 §55 负结果

### Step 4：测试 + 落档
- `tests/test_position_sizing.py`：测试仓位计算函数的边界条件（空数据/单日/NaN/截断）
- pytest 验证 td0_strategy 改动不破坏现有行为（position_scale=1.0 时与原版完全一致）
- 落档 §55 到 backtest-log

## 工程约束

1. **不触碰 FROZEN champion**（18 因子/HFLGBModel/label 全不动）
2. **复用 rolling_90d_result.pkl**（不重训模型）
3. **position_scale 默认 1.0**（向后兼容，不破坏现有行为）
4. **不引入自定义抽象层**（仓位计算用纯函数，不是类继承）
5. **td0_strategy 改动最小化**（仅加一行 `value *= self.position_scale`，由外部计算传入）
6. **无 look-ahead**（所有仓位信号只用 T-1 及之前的数据）

- `qlib_ifind_beta/td0_strategy.py` 改动（~5 行）
